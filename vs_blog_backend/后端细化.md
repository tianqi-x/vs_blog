# VS Blog 后端建设细化

## 当前状态

- 已有 Spring Boot 启动入口、公开健康检查、PostgreSQL/Flyway 配置，以及 Session 管理员认证。
- 已实现分类 CRUD、文章 CRUD 与公开读取、标签 CRUD/公开列表、作品 CRUD 与公开读取；管理接口要求 `ROLE_ADMIN`。
- 已实现文章个人补充记录的列表、创建、更新和删除；每条记录按文章 ID 隔离，API 仅授权管理员可访问。
- 阶段5已实现公开文章搜索和本地图片上传/元数据 API；图片二进制存放于可配置文件系统目录，数据库只保存 URL 与元数据。
- 阶段6增加公开分类列表（只包含已发布且公开文章使用的分类）和 CSRF 令牌端点；令牌响应同时包含 `headerName` 与 `token`，前端应按返回的请求头名称发送令牌。
- 搜索覆盖文章标题、Markdown 正文、标签名称和 slug，并限制为 `published + public`；媒体上传限制 PNG/JPEG/GIF、10 MB，上传/元数据操作要求管理员。
- 请求/响应使用 DTO；参数校验与统一错误响应覆盖无效参数、资源不存在和 slug 冲突。
- 文章状态/可见性以及作品状态/可见性转换为数据库要求的小写值；公开读取仅允许 `published + public`。
- 作品的 JSONB 技术栈/图片集，以及文章标签、作品文章关联已映射到 V1 中对应字段和关联表。
- Maven 依赖已包含 Spring Data JPA、Validation、Security、Flyway 和 PostgreSQL Driver；Java 目标版本为 21，与项目需求一致。
- 数据库初始结构已按 Flyway 版本化管理，脚本位于 [`src/main/resources/db/migration/V1__initial_schema.sql`](src/main/resources/db/migration/V1__initial_schema.sql)。仓库根目录的 [`blog_schema.sql`](../blog_schema.sql) 与其内容保持一致，差异仅为事务包装（`BEGIN/COMMIT`），用于离线数据库设计存档。
- 自动化测试覆盖健康检查、认证、分类、文章状态/可见性和 slug、标签、作品公开权限及关联内容过滤，以及搜索和媒体文件/API 行为。
- 当前本地 PostgreSQL 已可连接，数据库记录为 V1 baseline；搜索 SQL 已在 PostgreSQL 上只读验证。应用启动与 Hibernate `ddl-auto: validate` 尚未确认，MockMvc/服务层测试不替代该运行时验收。

相关实现：[`pom.xml`](pom.xml)、[`application.yml`](src/main/resources/application.yml)、[`SecurityConfig.java`](src/main/java/com/vsblog/config/SecurityConfig.java)、[`ApiExceptionHandler.java`](src/main/java/com/vsblog/api/ApiExceptionHandler.java)、[`V1__initial_schema.sql`](src/main/resources/db/migration/V1__initial_schema.sql)。需求依据见仓库根目录 [`需求整理.md`](../需求整理.md)。

## 建设顺序

### 1. 固化数据库迁移流程（已完成校准）

当前项目已将初始结构纳入 Flyway 管理：`src/main/resources/db/migration/V1__initial_schema.sql` 作为版本 1，覆盖 `blog_admin_users`、`blog_categories`、`blog_tags`、`blog_articles`、`blog_projects`、关联表和触发器。新数据库可从空库创建；已有数据库若未执行 Flyway 历史记录，则应按 `baseline-on-migrate: true`、`baseline-version: 1` 的策略让应用跳过初始建表步骤，并在启动前确认表结构与 V1 版本一致；后续结构变更只新增更高版本迁移，不直接修改已应用的脚本。

**完成检查：** 空数据库可通过迁移建表；现有数据库能按既定 baseline 启动；Hibernate `ddl-auto: validate` 通过。

### 2. 实现管理员认证与会话

- 实现管理员用户的数据访问和认证服务；密码只保存安全哈希。
- 提供登录、登出和当前会话接口，采用服务端 Session 与 HttpOnly Cookie。
- 安全地初始化首个管理员，不在代码或默认配置中写入固定密码。
- 保留 CSRF 防护，并验证开发环境前端通过 Vite 代理访问 API 的流程。
- 明确公开接口与管理员接口的访问规则；未登录请求不得访问管理功能。

**完成检查：** 登录成功后可建立会话；错误凭据不能登录；登出后会话失效；无会话不能访问管理接口；健康检查仍公开。

### 3. 统一 API 基础约定

确定请求和响应 DTO、参数校验、分页与排序、统一错误响应及 slug 冲突处理方式。API 不直接返回 JPA 实体，避免暴露内部字段或因实体关联产生意外序列化。

**完成检查：** 参数错误和资源不存在等情况返回稳定、可测试的响应格式；列表接口分页行为一致。

### 4. 完成分类与标签管理

实现分类、标签的增删改查。覆盖名称、slug 唯一性，分类描述与排序，并按需求限制每篇文章最多关联一个分类。

**完成检查：** 管理操作均需认证；重复 slug 被明确拒绝；列表排序稳定；关联数据约束正确。

### 5. 完成文章管理和公开读取

- 实现文章创建、编辑、删除、详情和分页列表。
- 支持 `draft`、`published`、`archived` 状态，以及 `private`、`public` 可见性。
- 实现文章与分类、标签关联、稳定 slug、发布时间与更新时间规则。
- 将公开读取与管理接口分开：公开接口只返回已发布且公开的文章；草稿和私密文章只能由获准的管理员访问。

**完成检查：** 覆盖状态和可见性组合、未授权访问、slug 唯一性及分类/标签关联的测试。

### 6. 完成作品集与个人补充记录

实现作品的管理和公开读取，支持技术栈、链接、展示排序、精选标记及关联文章。实现文章个人补充记录，并限制为本人访问。

**完成检查：** 公开列表不泄漏私密作品或关联的私密内容；补充记录接口必须经过认证和授权。

### 7. 增加搜索与图片元数据（实现已完成）

先使用 PostgreSQL 实现按标题、正文和标签检索，再按部署方案确定图片保存位置，并提供图片元数据管理。数据库保存媒体 URL 和元数据，不直接保存图片二进制。

**完成检查：** 搜索结果遵循文章发布和可见性规则；图片上传及访问策略与部署环境一致。

### 8. 补齐验证和运行文档

在现有健康检查测试之外，为认证、安全边界、服务层规则、API 行为和 Flyway 迁移补充测试。用 PostgreSQL 验证迁移和 JPA 映射；更新运行说明、环境变量、数据库初始化和测试命令。

**完成检查：** 新环境按文档可启动；迁移可重复验证；`mvnw test` 通过；关键管理和公开访问规则有自动化测试覆盖。

## 当前 API 约定

| 用途 | 接口 | 权限 |
| --- | --- | --- |
| 健康检查 | `GET /api/health` | 公开 |
| 公开文章 | `GET /api/articles`、`GET /api/articles/page?page=0&size=10`、`GET /api/articles/{slug}` | 公开；仅返回 `published + public` |
| 公开搜索 | `GET /api/search?q=word&page=0&size=10` | 公开；仅返回 `published + public` 文章 |
| 公开分类 | `GET /api/categories` | 公开；仅返回被 `published + public` 文章使用的分类 |
| 文章管理 | `GET/POST /api/admin/articles`、`GET/PUT/DELETE /api/admin/articles/{id}` | 管理员 |
| 分类管理 | `GET/POST /api/admin/categories`、`GET/PUT/DELETE /api/admin/categories/{id}` | 管理员 |
| 公开标签 | `GET /api/tags` | 公开 |
| 标签管理 | `GET/POST /api/admin/tags`、`GET/PUT/DELETE /api/admin/tags/{id}` | 管理员 |
| 媒体管理 | `GET/POST /api/admin/media`、`PUT/DELETE /api/admin/media/{id}` | 管理员；上传使用 multipart |
| 媒体文件 | `GET /api/media/{id}` | 公开；按 UUID URL 访问 |
| 公开作品 | `GET /api/projects`、`GET /api/projects/{slug}` | 公开；仅返回 `published + public` |
| 作品管理 | `GET/POST /api/admin/projects`、`GET/PUT/DELETE /api/admin/projects/{id}` | 管理员 |
| 个人补充记录 | `GET/POST /api/admin/articles/{articleId}/notes`、`PUT/DELETE /api/admin/articles/{articleId}/notes/{noteId}` | 管理员；记录限定所属文章 |
| CSRF 令牌 | `GET /api/admin/csrf` | 公开；返回 `headerName` 和 `token`，仅用于后续带会话的状态变更请求 |

统一错误 JSON 使用 `error` 和 `message` 字段；参数错误返回 400、资源不存在返回 404、重复 slug 返回 409。DTO 的枚举 JSON 值使用 `DRAFT`/`PUBLISHED`/`ARCHIVED` 与 `PRIVATE`/`PUBLIC`，数据库存储值按迁移约束转换为小写。

## 建议的首个可交付切片

媒体默认保存目录为 `MEDIA_STORAGE_DIR`（默认 `./var/media`，相对于后端工作目录）。媒体 URL 为公开读取；仅管理员可以上传和维护元数据。不得将敏感图片作为媒体上传；生产环境须使用持久化磁盘，横向扩展时改用共享文件存储或对象存储。当前本地实现支持 PNG/JPEG/GIF，单文件上限为 10 MB。

搜索与本地媒体功能已实现。前端公开浏览和管理 CRUD 已完成代码接入；需在应用可启动后验证开发代理、Session Cookie、CSRF 与实际 API 的端到端行为。应用对现有 PostgreSQL 的启动与 Flyway/JPA 校验仍未确认。
